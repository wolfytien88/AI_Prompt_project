# 待辦清單 App 評分 Rubric

四項標準各打 1–5 分。**任一項低於門檻即判定不通過**，不以平均分數判定。

| 標準 | 門檻 | 看什麼 |
| --- | --- | --- |
| 功能完整度 | 4 | feature_list.json 中標為通過的項目，實測是否真的可用 |
| 產品深度 | 3 | 是否只做到表面，例如有按鈕但沒有作用、錯誤情況沒有處理 |
| 視覺設計 | 3 | 版面是否一致、狀態是否清楚，逾期等狀態不能只靠顏色表達 |
| 程式品質 | 3 | 是否遵守分層、make lint 與 make test 是否通過、有無重複程式 |

## 分數定義

### 功能完整度（門檻 4）
- 5：標為通過的項目全部實測可用，未完成項目也如實標為 false
- 4：最多一項標為通過的項目有小瑕疵，主要流程都可用
- 3：有一項標為通過的項目實測失敗
- 2：多項標為通過的項目實測失敗
- 1：主要流程（新增、完成、刪除）無法使用

### 產品深度（門檻 3）
- 5：錯誤處理、空狀態、邊界情況都完整
- 3：主要情況完整，少數邊界情況未處理
- 1：功能只是空殼，例如按鈕存在但沒有作用

### 視覺設計（門檻 3）
- 5：版面一致、狀態清楚、有明確的視覺主題
- 3：可用且清楚，但樣式平淡或有少數不一致
- 1：版面錯亂，或狀態只能靠顏色分辨

### 程式品質（門檻 3）
- 5：分層清楚、測試涵蓋業務邏輯、lint 與 test 全過
- 3：lint 與 test 通過，但有重複程式或測試不足
- 1：lint 或 test 失敗

## 校正
正式使用前，拿 2–3 份已知好壞的成果，比較 Evaluator 與講師的評分；差距超過 1 分的標準，回頭修改 prompts/evaluator.md 的說明或加入附分數拆解的範例。
