# 待辦清單 App 產品規格

> 本規格是 Planner 的輸出範例。輸入的需求只有一句：「做一個可以設定截止日期、會提醒逾期的待辦清單網頁。」
> Planner 只定交付物與高層設計，不指定實作細節。

## 1. 產品目標

讓個人使用者在單一網頁上管理待辦事項：快速新增、標記完成、依狀態篩選，並透過截止日期看出哪些事情已經逾期。

## 2. 使用者

一位使用者、單一裝置。不需要登入、帳號或多人協作。

## 3. 功能需求

### 3.1 清單與新增
- 首頁顯示所有待辦；沒有待辦時顯示「目前沒有待辦事項」。
- 在輸入框輸入標題後按 Enter 即新增，新增後輸入框清空。
- 標題空白或只有空格時不新增，並顯示錯誤提示。
- 標題超過 200 字時不新增，並顯示錯誤提示。

### 3.2 狀態操作
- 每筆待辦可勾選為完成，再勾一次恢復未完成。
- 已完成的待辦以刪除線顯示。
- 每筆待辦可刪除。
- 雙擊標題可編輯，按 Enter 儲存、按 Esc 取消；編輯成空白時不儲存。

### 3.3 篩選與統計
- 提供「全部 / 未完成 / 已完成」三種篩選。
- 顯示未完成的數量，例如「剩 3 項」。
- 提供「清除已完成」按鈕，一次刪除所有已完成項目。

### 3.4 截止日期
- 新增或編輯時可設定截止日期（可不設定）。
- 截止日期早於今天且未完成的待辦，以醒目樣式標示「已逾期」，不能只靠顏色表達。
- 清單依截止日期排序，沒有截止日期的排在最後。

### 3.5 資料保存
- 重新整理頁面或重新啟動伺服器後，資料仍在。

## 4. API 需求

- `GET /api/health`：健康檢查。
- `GET /api/todos`：回傳全部待辦（JSON）。
- 新增、修改、刪除各有對應 API；不合法的輸入回傳 HTTP 400 與錯誤訊息。

## 5. 非功能需求

- 只使用 Python 標準函式庫，不安裝外部套件。
- 遵守 `docs/architecture.md` 的分層規則：types → repo → service → ui。
- 介面文字使用繁體中文。
- 每個功能都要能用瀏覽器實際操作驗證，不只靠單元測試。

## 6. 不在範圍內

登入、多人共用、行動 App、通知推播、標籤與分類。
