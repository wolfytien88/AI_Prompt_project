# Harness 檢核清單

上線前與專題實作自評時逐項檢查。每一項都要能指出對應的檔案或證據。

## 設計

- [ ] 規格與完成定義寫在檔案裡（`spec.md`、`AGENTS.md`）
- [ ] 指令檔精簡，細節放在其他文件，用到才讀（漸進揭露）
- [ ] 工具以通用工具為主；寄信、付款、刪除等高風險動作改用宣告式工具並加確認
- [ ] 狀態檔能讓全新的上下文接手：開新 Session 只讀檔案就知道下一步

## 安全

- [ ] 不可逆動作有 Hook 阻擋或人工確認（對照可逆性分級）
- [ ] 機密不在 Agent 碰得到的地方：不放工作目錄、不寫進程式、不進沙箱
- [ ] 沙箱限制可寫目錄與網路，並確認預設可寫範圍（例如 `/tmp`）沒有敏感資源
- [ ] Hook 用「應該被擋」與「不該被擋」的指令都驗證過
- [ ] Codex 的專案已信任，Hook 已在 `/hooks` 審查並信任
- [ ] 做過紅隊測試，紀錄哪一層擋下、哪些沒擋住

## 驗證與維護

- [ ] 驗證自動化，評分者獨立於生成者（獨立 Evaluator 或機械化檢查）
- [ ] 有固定的 Eval 測試集，含刁鑽題
- [ ] 換模型或改設定時重跑 Eval
- [ ] 做過拆除實驗，不再需要的元件已移除
